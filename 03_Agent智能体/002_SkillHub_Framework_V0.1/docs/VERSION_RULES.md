# 版本管理规范

## 1. 版本模型

Framework、Skill、Knowledge 和 Tool 分别维护可追踪版本。代码版本遵循语义化版本 `MAJOR.MINOR.PATCH`：

- MAJOR：职责边界、公共接口或数据契约发生不兼容变化；
- MINOR：向后兼容地新增能力；
- PATCH：向后兼容的问题修复和文档澄清。

## 2. Constitution 版本

Constitution 是最高级架构契约。修改不可违反规则的含义、依赖方向或安全边界，至少触发 Framework MINOR；造成不兼容时触发 MAJOR。纯文字澄清可使用 PATCH。

## 3. Skill 版本

Skill 名称是稳定标识，不因实现重构而改变。输入输出、错误语义或业务结果发生不兼容变化时升级 MAJOR；新增可选能力升级 MINOR；修复升级 PATCH。

## 4. Knowledge 与 Standards 版本

知识更新必须记录来源版本、生效日期、状态和变更摘要。Standards 禁止无版本覆盖。历史任务必须能定位当时使用的条目版本。

## 5. Tool 版本

Tool 的输入、输出、副作用和权限属于版本契约。外部系统变化需通过适配层隔离；无法兼容时提供新版本并保留迁移期。

## 6. 发布要求

每次发布必须包含变更日志、兼容性说明、迁移步骤、测试证据和已知限制。不得仅修改版本号而缺少对应审计记录。

## 7. 禁止事项

禁止复用已发布版本号、重写历史标签、静默修改 Knowledge 来源、在 PATCH 中引入破坏性接口变化。
