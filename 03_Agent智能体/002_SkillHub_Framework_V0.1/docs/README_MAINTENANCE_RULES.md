# README Maintenance Rules

## 1. README 定位

README 是 Project Dashboard（项目驾驶舱），用于让开发者和决策者快速了解：

- 项目当前状态；
- 架构总览；
- 版本进度；
- 核心能力；
- 演进路线；
- 文档入口。

README 不是 Development Log（开发日志），不记录：

- 每次代码修改；
- Bug 修复过程；
- 函数调整细节；
- 逐提交实现说明。

详细开发记录由以下载体管理：

- Git commit：记录单次代码与文档变更；
- CHANGELOG：记录面向版本和使用者的重要变化。

## 2. README 更新触发条件

### 必须更新

1. 进入新版本阶段，例如 V0.1 → V0.2；
2. 新核心模块加入，例如 Runtime、Skill Registry、Service Layer、MCP Client；
3. 系统架构、职责边界或关键数据流发生变化；
4. 重要能力正式上线、冻结、废弃或改变状态；
5. Roadmap、文档入口或版本冻结信息发生变化。

### 不需要更新

- 单个函数修改；
- 普通 Bug 修复；
- 参数微调；
- 不改变外部能力的内部重构；
- 测试实现细节调整。

上述细节应进入 Git commit，必要时汇总到 CHANGELOG。

## 3. README Dashboard 标准结构

README 至少包含：

1. `项目简介`；
2. `当前版本状态`；
3. `架构总览`；
4. `已完成模块`；
5. `当前开发任务`；
6. `Roadmap`；
7. `Documentation` 入口；
8. `Version History`。

状态信息必须反映当前分支和版本阶段，模块使用统一状态标识：

- ✅ 已完成；
- 🚧 开发中；
- ⬜ 未开始或待规划；
- 🧊 已冻结。

## 4. 图形规范

架构展示优先使用 Mermaid，适用于：

- 系统架构图；
- 数据流图；
- 模块关系图；
- 版本演进路线。

不要使用大量代码片段代替架构图。代码片段只用于最小运行示例或稳定公共接口，不承担架构说明职责。

## 5. 维护责任与审计

重大版本或核心模块状态变化必须在同一变更中同步维护 README。README 中的版本、Tag、完成状态和链接必须可由 Git 历史、测试或对应文档验证，禁止提前标记未完成能力。
