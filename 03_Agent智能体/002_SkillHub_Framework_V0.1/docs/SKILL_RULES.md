# Skill 开发规范

## 1. 定位

Skill 是一个单一、可注册、可测试、可审计的业务能力模块。Skill 执行业务流程，但不承担任务路由、知识存储或外部系统实现。

## 2. 必须遵守

1. 继承 Framework 规定的 `BaseSkill`。
2. 声明全局唯一且稳定的 `name`、清晰的 `description` 和可解释的匹配元数据。
3. 输入和输出必须有类型注解与明确契约；不得依赖未声明的全局状态。
4. 一个 Skill 只解决一个业务目标，复杂步骤封装为本 Skill 内部函数或 Service。
5. 所有依赖通过构造参数或显式上下文注入，便于替换和测试。
6. 对关键判断、输入摘要、结果状态和失败原因保留审计事件。

## 3. 严格禁止

- Skill 调用、实例化、注册或路由其他 Skill；
- Skill 直接导入或调用 Knowledge Router；
- Skill 直接读取 `data/knowledge`、`data/standards` 或模板文件；
- Skill 直接导入、实例化或调用 Tool；
- Skill 直接访问文件系统、网络、数据库或外部 API；
- 在 Skill 中隐藏 Agent、自动化流程或动态代码执行；
- 用宽泛默认 Skill 吞掉本应明确失败的业务任务。

## 4. 允许的依赖

```text
Skill → TaskContext / 领域数据类型 / Service 接口
```

Service 返回的数据必须已完成知识或工具适配，Skill 只处理业务语义和流程判断。

## 5. 错误与结果

Skill 应区分输入错误、业务规则不满足、依赖不可用和内部错误。不得返回伪造成功结果，不得吞掉异常。对外错误应稳定、可测试，内部细节进入受控审计日志。

## 6. 测试门槛

每个 Skill 至少覆盖：正常路径、空输入、非法输入、依赖失败、边界条件和审计事件。测试必须证明其没有调用其他 Skill，且没有直接依赖 Knowledge 或 Tools。

## 7. 审查清单

- 是否只有一个业务目标？
- 是否可以独立测试？
- 是否通过 Router 注册而非被 Agent 硬编码实例化？
- 是否仅通过 Service 获取知识或外部能力？
- 输入、输出、错误和版本是否可审计？
